# TableAgent 研究方向设计：触发 × 多样性 × 决定权

> 本文档是**动工前的方向设计与依据**，不是实现代码，也不替代 `PLAN.md`（工程规划）与 `HANDOFF.md`（交接）。
> 生成时间：2026-07-02。基于对现有 1000 题跑批 trace 的实测审计。

---

## 0. 一句话

我们把论文主轴从"控制 verify"锐化为一条流水线——**触发（哪些题值得深究）→ 造多样性（生成几个候选）→ 决定权（谁来拍板选答案）**——并用数据证明：错题在这三个环节都有分布，而**"谁拍板"和"漏检"这两块过去几乎没被系统研究过**。

---

## 1. 大白话：我们在研究什么

### 系统现在长什么样

- **生成器（Generator）**：一个模型，用写 pandas 代码的方式把答案算出来，然后 `submit_answer` 提交。
- **检查器（Verifier）**：另一个模型（建议不同厂商），在提交后复查。觉得不对就打回，两边"吵一架"（debate），来回几轮。
- **拍板（finalize）**：debate 结束后，从"这道题一路上提交过的所有答案"里挑一个当最终答案。

### 你（用户）提出的核心问题

现在这个"最终挑哪个答案"的活儿，**既不是生成器干的，也不是检查器干的，而是一段写死的代码规则**在挑（大意是"挑第一个检查器点头的那个"）。

代码位置见 `src/agent.py` 的 finalize 段（约 483–517 行），选择优先级链是：
`当前答案 → 第一个通过验证的 → incumbent → 第一个候选 → run_python 结果 → 兜底`。

你的直觉：这个"**拍板权**"值不值得当成一个实验维度——交给生成器自选、交给检查器、还是请**第三方模型当裁判**？

**为什么这是个好问题**：你们之前的诊断（见 `HANDOFF.md` §2.3）已经发现，很多题**错在"拍板挑错了"，不是错在"算错了"**（典型：nt-11778，后期已经提交了对的 38，却回退到早期的 36）。也就是说，正确答案本来就在候选池里，只是被规则丢掉了。

## 2. 数据发现：我去 trace 里挖了三件事

审计脚本：`scripts/candidate_diversity.py`（用官方 evaluator 归一化做语义去重与匹配，`12467` 和 `12,467` 不算分歧）。
数据：`results/agent_qwen3.6-35b-a3b_mine_1000.json`（主）与 `..._mine2_1000.json`（对照）。

### 发现 1：绝大多数题根本"没得挑"

只有触发过 debate 的题，候选池里才会出现多个不同答案；没吵过架的题，池子永远是单一答案。

| 子群 | 数量 | 候选池里 >1 个不同答案的比例 |
|------|------|------|
| 没触发 debate | 792 (79%) | **0%** |
| 触发了 debate | 208 (21%) | **~36%** |

→ **"决定权/拍板"实验只在"吵过架"的 ~20% 题上有意义。**

### 发现 2：在吵过架的题里，拍板挑错的代价很大

假设有个"完美裁判（oracle selector）"总能从候选池里挑出对的：

| 人群 | 现状正确率 | 完美裁判正确率 | 纯靠"挑对"能回收 |
|------|------|------|------|
| debate 子群 (mine_1000) | 68.8% | 79.3% | **+22 题 (+10.6pt)** |
| debate 子群 (mine2_1000) | 62.0% | 78.0% | **+8 题 (+16pt)** |

→ **你的直觉对，"谁拍板"确实值钱**——现有规则在吵架题上白白丢了 10~16 个点。

### 发现 3：但全局天花板只有 +2.3 个点（重要清醒剂）

| 跑批 | 现状 | 完美裁判 | 纯选择的全局天花板 |
|------|------|------|------|
| mine_1000 | 86.1% | 88.0% | **+2.3pt** |
| mine2_1000 | 85.6% | 86.3% | +0.9pt |

因为 79% 的题从头到尾只有一个候选，裁判再神也没得挑。

→ **单独研究"换谁拍板"上限不高。必须配一根"先造出值得挑的候选"的杆。**

### 发现 4（关键校准）：一半以上的错题，压根没进 debate

这是把上面串起来的核心。错题分布：

| 跑批 | 没debate的错题 | 占全部错题 | 有debate的错题 | 占全部错题 |
|------|------|------|------|------|
| mine_1000 | 74 | **53.2%** | 65 | 46.8% |
| mine2_1000 | 125 | **86.8%** | 19 | 13.2% |

- 没触发 debate 的题正确率看着很高（90.7% / 86.8%），**但错题的大头（53%~87%）恰恰藏在这里**——这些是检查器"自信地放行了错误答案"的**漏检（false negative）**。
- 这类错题**光靠造多样性 + 换裁判救不了**，因为它们根本没进入仲裁流程。它们需要更好的**触发**——先把"看着没问题、其实错了"的题揪出来。

## 3. 结论：三根杆其实是一条流水线

错题按"卡在哪一环"分成两类，归不同的杆管：

- **A 类｜进了 debate，但候选/拍板没搞对**（占错题 47% / 13%）→ 归"多样性 + 决定权"管。
- **B 类｜压根没进 debate 的漏检**（占错题 53% / 87%）→ 归"触发"管，最难，因为它们正是检查器认为"没问题"的题。

于是主轴是一条链，错题在每一环都有分布：

```
触发 (Trigger)          造多样性 (Diversity)        决定权 (Decision-Right)
哪些题值得深究?    →     为这些题生成几个候选?   →    谁来拍板选最终答案?
─────────────           ──────────────────         ────────────────────
识别漏检(B类)            多轨/多温度/skill变体       generator自选 / verifier
= false-negative        = 抬高"天花板"有多高        / 第三方裁判 / 陪审团 / 加权投票
predictor                                          = 决定你离天花板多近
```

**核心论点（论文卖点）**：
1. **裁决（对不对）与选择（选哪个）应当解耦**；现在检查器把两件事一把抓（"first_verified"），这是独立于"检查器强不强"的内伤点。
2. **选择红利被候选多样性 gate 住**——这是一个反直觉、可量化的发现。
3. **一半以上的错题是漏检**，落在触发环节，而非选择环节；这重新校准了"该往哪使劲"。

## 4. 三根杆展开

### 杆 A — 触发（Trigger）
- **目标**：识别 B 类漏检——检查器会放行、但其实错了的题。
- **候选做法**：always / never / 规则触发 / **学习式触发（helpfulness / false-negative predictor）**；用 generator↔verifier 分歧、代码执行信号、答案是否可在表中定位等作特征。
- **难点**：这些题恰恰是检查器自认为"没问题"的，识别难度最高。这是最硬也最有区分度的一环。

### 杆 B — 造多样性（Diversity Generation）
- **目标**：为"值得深究"的题产出**语义上不同**的候选，抬高 oracle 天花板。
- **候选做法**：多轨采样（不同温度/种子）、skill 变体、让 verifier 主动提反例/反解。
- **纪律**：**选择性做，不全局做**（发现 1 已证明 79% 的题只有单候选、且正确率高，全体多轨是浪费）。触发决定对谁做。

### 杆 C — 决定权（Decision-Right Allocation）
把"选择（selection）"（也可延伸到"停止"）的决定权显式交给一个角色。3 决定 × 3 角色的仲裁矩阵：

| 决定 \ 角色 | Generator 自选 | Verifier | 第三方 Arbiter / 陪审团 |
|------|------|------|------|
| **裁决 verdict** | 同源偏见，看不见自己的坑 | 现状；既裁又选易复合偏见 | 角色分离，误差去相关 |
| **停止 stop** | 易过早自满 | 现状（重试上限/drift guard） | 可独立判"还值不值得辩" |
| **选择 selection** | self-consistency / USC | 现状 first_verified | LLM-as-judge / jury / 加权投票 |

- **generator 自选**：便宜、懂自己推理；但同源偏见（会放行自己看不见的错，见 `HANDOFF.md` §2.3）。
- **verifier**：跨厂去相关（Claude 正向）；但既裁又选会复合偏见（Gemini 组合 −3）。
- **第三方 arbiter / 陪审团**：只在 debate transcript + 候选 + evidence 上做一次裁定；可用更强/更专模型，或一组便宜异构模型投票（Panel-of-LLM）对冲单一 verifier 偏见。代价是多一次调用（用选择性触发对冲）。

## 5. 可借鉴的前沿 / 跨领域思路

- **LLM-as-Judge / 陪审团（PoLL）**：一组便宜异构模型投票，比单个贵裁判更公允、偏见更低——直接对冲"单一 verifier 系统偏见"。
- **Debate → 弱裁判也能达真相**（Khan et al.）：arbiter 不必最强，但要小心自家教训"更多轮 ≠ 更好"，贡献点应是**选择性 debate**。
- **Self-Consistency / Universal Self-Consistency (USC)**：按语义聚类投票，不需精确匹配，适配表格答案格式漂移（日期/千分位/列表）。
- **Verifier-weighted voting**：投票权重 = verifier 置信度，把 self-consistency 与 verify 缝在一起。
- **过程级验证 PRM（"Let's Verify Step by Step"）**：现有 compute_recheck 是结果级（ORM），和 solver 共享偏见；PRM 在 pandas trace **每一步**（选列/过滤/聚合）校验，更可能在口径歪的那一步就抓住。
- **级联 / 分诊（cascade，来自 ML serving / 医疗 AI）**：便宜路径先答，只在分歧/低置信时升级到昂贵 arbiter → cost-accuracy Pareto，稳的效率故事。
- **Conformal prediction**：输出带覆盖率保证的候选集合，arbiter 在集合内选 → 给表格 QA 带来统计保证的新角度。
- **把"分歧"当特征**：generator↔verifier 不一致本身就是"难/歧义"的强信号，可直接喂给触发预测器。

## 6. 指标（沿用并扩展）

- **Final Acc**：最终正确率。
- **PreVerify Acc**：首次 submit 的正确率（verify 介入前）。
- **PostVerify / Net Gain**：verify 带来的净变化（可正可负）。
- **Damage Rate**：首次对 → 最终错的比例（debate/选择"改坏"的代价）。
- **Oracle-Selector Gap**：现状选择器距"完美裁判"的差距（本文档发现 2/3 的量化）。
- **False-Negative Recall**（触发专用）：漏检题被触发环节成功召回的比例。
- 统计：paired bootstrap CI + McNemar。

## 7. 落地顺序（按信息量/成本比排，省钱的先做）

1. ✅ **多样性 / 可回收审计**（`scripts/candidate_diversity.py`，已完成）——见第 2 节发现。
2. **补全 debate 硬题池子还原**：从 wrongset295 / screen50 的 `trace.submit_answer` 事件重建候选池，拿到**硬题人群**上更干净的 oracle 上限（纯离线、零成本）。
3. **决定权离线重放 harness**：同一批 debate trace 上，把选择函数换成 {generator自选 / verifier / 第三方arbiter / 加权投票 / 各种规则}，对每个报 Final Acc / Net Gain / Damage Rate / 距 oracle 的 gap（除第三方 arbiter 需补调用外，近乎免费）。
4. **HiTab adapter + pilot**（已定主战场）：干净数据集上重跑杆 B×杆 C 主实验。
5. **触发（杆 A）实验**：false-negative predictor，攻 B 类漏检（占错题大头）。
6. **多样性（杆 B）在线实验**：选择性多轨生成，看天花板能抬多高，再看决定权能吃下多少。
7. **级联收尾**：确定哪个 arbiter 赢之后，做最终 cost-accuracy Pareto 曲线。

## 8. 前置风险 / 注意点

- **候选多样性是离线重放的前提**（发现 1/3）：现有主跑批全局多样性低，重放实验必须 condition 在 debate 子群，或先做杆 B 注入多样性。
- **B 类漏检最难识别**：它们是检查器自认为"没问题"的题，触发研究的硬核。
- **WTQ gold 有噪音/歧义/不可达**（`HANDOFF.md` §3.5）：arbiter 修不了 gold 错；主实验放 HiTab（更干净），WTQ 报"歧义子集"表现。
- **成本**：第三方 arbiter / 多轨生成都加成本，必须用选择性触发对冲并在论文报成本。
- **不要盲目全体多轨**（发现 1/4）：79% 的题单候选且正确率高，多样性生成必须选择性做。
