你的工作框架很有价值——把“触发-多样性-决定权”拆成三条独立的研究轴，本身就比常见的端到端优化要锐利。既然你觉得创新性还不够，我基于你的框架和2025-2026年的前沿进展，把三根杆各自能叠加的“大招”梳理了一下。

### 🎯 杆 A — 触发 (Trigger)：主攻“漏检”，让它无处遁形

你的核心痛点是**检查器“自信地放行错误答案”**（B类漏检，占错题的53%-87%），这部分最难啃，也最有研究价值。

**1. 借鉴多智能体“批判-修正”闭环**
可以看看 `Table-Critic` 框架。它有个 `Judge` 智能体专门负责检测推理步骤中的错误——这恰好是你现有检查器的盲区（它只在最终答案层面做验证，看不到中间步骤）。你可以让 `Judge` 专门审查生成器的 pandas 代码执行轨迹，在“选列/过滤/聚合”的每一步寻找逻辑断裂，有望把漏检的 B 类题提前揪出来。

**2. “过程监督”（Process-Supervised Reward Model）**
借鉴 OpenAI “Let's Verify Step by Step”的思路，你的 `compute_recheck` 目前是结果级验证（ORM）。可以训练或 prompt 一个 PRM，对 pandas 代码的**每一步中间结果**打分，一旦某步得分低就立刻触发 debate。这比等代码跑完再验证要早得多。

**3. 用“分歧”本身作为触发信号**
把 generator 和 verifier 之间的**不一致程度**、代码执行是否报错、答案是否能在表中直接定位等信号，喂给一个轻量级分类器（如你的 false-negative predictor）来预测“这道题会不会翻车”。这比静态规则更聪明，可以主动挖掘那些表面平静、实则危险的题。

### 🎨 杆 B — 造多样性 (Diversity Generation)：把“候选池”做大、做真

多样性是你“决定权”研究的上限。你的数据已经证明，79%的题只有一个候选，导致选择红利被封死。

**1. “多模态路由”生成不同视角的答案**
`TableDART` 的思路是：对同一个 query，分别用纯文本、纯图像等不同模态处理表格，再动态选择或融合。你可以让生成器基于表格的 **Markdown/HTML 文本视图**和**截图图像视图**分别写代码，天然产出视角不同的候选答案，多样性会显著提升。

**2. “模板驱动”的变体生成**
借鉴 `TeLL` 框架，你可以预设几种“解题风格模板”（比如“先过滤再聚合”、“先聚合再过滤”、“用SQL实现”、“用pandas实现”），让生成器按不同模板各走一遍。这比单纯调温度更可控，产出的候选在**解题路径**上就有本质差异。

**3. “对抗性”多样性生成**
让 verifier 在 debate 中**主动提出反例或反解**（“如果这样理解问题呢？”），逼迫 generator 产出覆盖不同语义解释的答案。这能把“语义上的多样性”真正做出来，而不仅仅是数值上的扰动。

### ⚖️ 杆 C — 决定权 (Decision-Right)：从“谁拍板”升级为“如何聪明地拍板”

决定权是你论文最性感的切入点。现有“first_verified”规则太粗暴，第三方 arbiter 虽然好但贵。你需要更精巧的方案。

**1. “置信度校准 + 加权投票”**
与其让 arbiter 做一次硬判决，不如让多个 verifier 或生成候选**带置信度投票**。你可以借鉴 `CalibraEval` 的思路，校准每个 verifier 的预测分布来缓解选择偏见。也可以参考 SemEval-2025 冠军方案，用**置信度加权集成**来解决模型间的分歧。这样，即便单个 verifier 有偏见，投票也能对冲掉。

**2. “Conformal Prediction”提供统计保证**
这是从统计学跨界来的利器。Conformal Prediction 可以生成一个**包含正确答案的候选集合**，并给出统计覆盖率保证。你可以：
*   用它来**辅助 arbiter**：只让 arbiter 在 CP 给出的“高置信候选集”内做选择，降低决策难度。
*   用它来**决定是否触发 debate**：如果 CP 集合很小（模型很自信），就跳过 debate 省成本；如果集合很大（模型很犹豫），就触发深度辩论。

**3. 把“选择”本身交给一个轻量级、可学习的模型**
不要用写死的规则，而是训练一个小模型（如 MLP），基于 debate 过程的各种特征（各候选的验证通过情况、置信度、答案类型等）来学习**什么时候该选哪个候选**。这能让你的“决定权”从一个工程规则升级为一个可学习、可优化的组件。

### 💎 总结与行动建议

你的框架已经很有根基了。要进一步提升创新性，关键是**在每个环节引入更精巧的机制，而非简单的角色替换**：

1.  **杆A (触发)**：从“结果验证”深入到“**过程验证**”（借鉴 Table-Critic 的 Judge 或 PRM），主动发现推理链条上的裂痕。
2.  **杆B (多样性)**：从“参数扰动”升级到“**路径与模态扰动**”（借鉴 TableDART 的多模态路由或模板驱动），产出真正有语义差异的候选。
3.  **杆C (决定权)**：从“谁来做”升级到“**如何聪明地做**”（借鉴 Conformal Prediction 或可学习的选择器），引入统计保证和可优化的决策逻辑。
4.  **系统级创新**：将三根杆串联成一个**级联系统**（Cascade System），用“触发”来控制成本，用“多样性”来抬升天花板，用“决定权”来逼近天花板。

你可以优先把 **Conformal Prediction** 和 **Table-Critic 的过程验证**作为两个高优先级的“大招”来探索，它们分别对应你框架里的“决定权”和“触发”这两个最有区分度的环节，理论深度和实证潜力都很大。
